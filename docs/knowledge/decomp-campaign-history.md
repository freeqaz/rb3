## Wave-Dispatch Strategy (durable lessons)

The proven loop for "keep going / exhaust every function": query `report.json` for units in the 90–99.99% range (≥1 real fn remaining, npct <100), pick top-match candidates (npct ≥97%) across *distinct* units to avoid agent collisions, dispatch ~8 parallel Sonnet agents in `run_in_background` mode each with **strict scope** (only the `.cpp/.h` pair; never touch `Mtx.h`/`CharHair.cpp`/`Platform/String.h`), then commit per wave.

Durable strategy findings:

- **Low-% structural decomp beats finishing waves.** Finishing waves (96%+ register-swap targets) average 30–50% conversion (3–5 wins of 8). Low-% structural decomp on stubbed bodies averages near 100% (an 8/8 wave was observed): many low-% functions are empty stubs (`MILO_ASSERT` + `return`) whose body is simply *missing* — implementing it takes 25%→95%+ in one rewrite. Prefer stubs over register-swap grinding.
- **Low-% workflow:** `bin/analyze-function -u UNIT SYMBOL` → Ghidra DWARF pseudo-C → DC3 cross-ref (`/home/free/code/milohax/dc3-decomp/src/system/`, ~87% complete, often portable verbatim with class-name swaps) → rewrite body → apply CW patterns *after* structural decomp.
- **Skip `obj/Dir.h` pattern hotspots** (Crowd, LightPreset, BandDirector, BandCharacter, World/Instance, GemTrackDir, FileMerger, Character, CameraShot): all hit the same byte-identical-post-link relocation issue from inlined `__as__`/`PostLoad` recursive `operator=`; cracking them needs `obj/Dir.h` edits with wide blast radius.
- **Verify against asm; hunt real bugs.** Many "stuck" functions have semantic bugs (wrong polarity, wrong member, missing call, wrong return type). `void X()` functions are frequently `T X()` — the asm's `r3=SRET` shape betrays a missing return value. Don't assume current source is semantically correct.
- **Reliably-convertible patterns** (~50% win rate): branch-polarity via early-return inversion; bool materialization via separate decl; ternary sign-flip; switch fallthrough; backward iteration; manual STL inline / template specialization; `erase(begin(),end())` vs `clear()`; named-local empty-functor byte-copy; CSE-defeat via `volatile` member reads; hoisting member loads to named locals; split decl-from-init to claim earlier callee-saved regs; `const` qualifier to flip register coloring; POD default-ctor toggle (BIDIRECTIONAL — add a ctor to flip `has_trivial_default_constructor` to false and inline the copy body, or remove it to go back to memcpy-style; only works on TRUE PODs). Full catalog in `docs/decomp/patterns/INDEX.md` and the MWCC-recipe memory hooks.
- **Hard at-limit signals — don't burn agents:** callee-saved register-swap cascades (IPA-driven coloring), `ADDRESS_RELOCATION_NOISE` (string-pool ordering), inlined `Mtx.h` Invert/FastInvert scheduling, `START_AUTO_TIMER` inline scheduling (**no `START_AUTO_TIMER` user is at 100% in RB3** — class-wide Timer.h blocker), `Vec.h Interp` FPR swaps, stlport `_Vector_impl::reserve` register allocation (header-locked, all non-trivial-T plateau 84–96%), `ClampEq` IPA float-load duplication, float-pool `@floatBase0` vs `@F_xxx` emission (IPA decision), branch-fusion peephole anomalies. **MILO_ASSERT-adjacent scheduling noise is ADDRESS_RELOCATION_NOISE in disguise** (e.g. `MatchesPatchCategory` in OutfitConfig.cpp): an extra `lis+addi @stringBase0` before a loop, or reordered `kAssertStr`/`@stringBase0` loads, come from the file string sitting at a NON-zero pool offset — target loads it lazily (`lis @ha` pre-loop, `addi r4,r30,@l` at the assert) when the offset is 0, vs eager full-address materialization when it isn't. Not source-fixable → AT_LIMIT.
- **Cross-cutting force multipliers:** one shared inline/header fix can cascade (`RangedDataCollection::RangedData` const-ref fixes 3 at once; `DoRemoveUntil` saved-begin trick fixes 4 template siblings). When N agents converge on one header root cause, **fix the header once with the full-rebuild gate** instead of bailing N times.
- **Build-infra gotchas in concurrent waves:** `Mtx.h Multiply(Matrix3,Matrix3,Matrix3)` inline asm conflicts with CharHair.cpp's local `Multiply` — guard with `#define CHARHAIR_LOCAL_MULTIPLY`; `Platform/String.h String operator+` must return a *reference* (agents "fix" this wrong — revert); `manifest 'build.ninja' still dirty after 100 tries` = configure-regen loop, clean `.ninja_lock`+`build.ninja`+`objdiff.json` and re-run configure.py.

## LLM "permuter-class" Bails — Verify Before Trusting (workflow)

LLM agents at wave-end routinely declare a residual "permuter-class"/"at-limit" (FPR-cascade, regswap, IPA scheduling) and bail. **Do not take the LLM diagnosis at face value — queue an actual permuter run to verify.** Protocol (freeqaz, 2026-05-26):

- If the function is inside an active fleet's pct band, the fleet attempts it eventually — nothing to do. If it's below the fleet floor (e.g. sub-80% while fleets cover 80%+), kick a non-overlapping targeted sweep. For a single function, `beam_search --symbol <mangled> --unit <unit>` goes deeper per-fn than `batch_auto`.
- Permuter CRACKS it → the bail was premature; cherry-pick the win and log the mutation pattern (often `asgn_swap`/`fma_reorder`/`stmt_reorder`/`boolmat`/`slot_pad`). Permuter ALSO stuck after 2+ rounds × 30 variants → genuinely permuter-class; add to a future-session list with the specific blocker.
- **Empirical evidence the protocol pays off (Wave-10 bails, 2026-05-26): 2 of 3 LLM bails were PREMATURE.** `BandPatchMesh::WorkVerts::ExtendTwin` 71.5→72.0%, `UtilDrawCigar` 65.7→67.0% both cracked further by the permuter; only `ClipDistMap::Draw` (f24 callee-saved FPR cascade) was confirmed genuinely permuter-class (LLM diagnosis correct). The same sub-80% sweep also landed bonus wins on functions no LLM was dispatched on (`StorePackedSong::EndianFix` 41.0→54.7%, biggest single delta). **Don't treat "at-limit" memory entries as gospel — re-run the permuter against the documented at-limit list periodically, since compiler-class ceilings shift when new permuter patterns land.** Caveat: same-named members on different types differ — `StorePackedSong/Page::EndianFix` improved but `StorePackedRanks::EndianFix` is a documented dead-end; don't generalize a verdict across siblings.

## GemPlayer::Hit Session (decomp recipe)

`GemPlayer::Hit` (`Hit__9GemPlayerFifiUi11GemHitFlags`, 4.8KB) 87.1→95.8% in one session. Reusable levers, in order applied:

1. `#pragma push` / `#pragma pool_data off` around the function (+5pp) — target uses per-symbol `lis/addi @LOCAL@msg` (unpooled) for static Messages; without it, base caches a `.bss` base.
2. Rename `static Message msg2(...)` → `msg` inside the nested `if (IsLocal())` scope — MWCC mangles the shadowed inner static as `@LOCAL@...@msg@1`, matching the target.
3. Float CSE via explicit float locals (`float numTotalF = (float)Count(...)`) (+1.1pp) — forces xoris/stw/lfd/fsubs interleave right after each `CountBitsInSlotType` call instead of deferring conversion.
4. Swap call order to match target (gemSlots `Count` before gem_hit_slots) — figured from `mr r3, r19` as TGT's first call arg.
5. Header edit: `DeltaTracker::PrintDeltas()` — removed the else `MILO_LOG` branch AND trailing `mCur = 0;` (+1.1pp; target's inlined PrintDeltas omits both).
6. `hitFlags = 1 | 8;` → `hitFlags |= 8;` (+0.2pp) — `ori` preserves running r16 vs `li` constant-fold.
7. Hoist `float msPlusOffset = ms + mSyncOffset;` before the branch (+0.3pp).

**Residual ~4% is plateau-class (not source-fixable):** a 45-instruction r16↔r17 register-swap cascade — target uses `_savegpr_16` (base `_savegpr_17`), promoting one extra value (the `.bss`/section base) to a callee-saved reg. Permuter (60–100 variants) confirmed the plateau (no improvement past 95.91%). **Best tools:** `run_diff_inspect mode=diagnose` (ROOT_CAUSES) + `mode=clusters` (structural inserts/deletes with context) + reading mangled local-static names + tracing arg-register flow through `mr r3, rN` before `bl`.

## SaveLoadManager::SetState Workstream (decomp recipe)

`SetState__15SaveLoadManagerFQ215SaveLoadManager5State` — a large two-switch function (exit switch on oldState = cleanup; entry switch on newState = 105 cases issuing I/O). Baseline 62.9% → RESOLVED to 99.6% normalized (`64c51cff`, AT-LIMIT).

- **Don't confuse with Poll.** Poll observes state and dispatches (`if (!IsDone()) return; SetState(next)`); SetState issues async I/O on entry (`if (!MountAsync(...)) MILO_FAIL(...)`). Confusing them wastes time.
- **Process:** pick a target state → look up its body label → read the asm body → identify `@stringBase0` offsets (map to MILO_FAIL strings) → decode vtable slot offsets (Cache.h: 0x14 IsConnectedSync, 0x24 GetFileSizeAsync, 0x28 ReadAsync, 0x2c WriteAsync; CacheMgr.h: 0x10 SearchAsync, 0x14 ShowUserSelectUIAsync, 0x20 MountAsync, 0x24 UnmountAsync, 0x28 DeleteAsync) → write C++ → `run_objdiff` immediately → revert-and-shrink-scope on regress. **Removing case bodies (even for default-mapped states) shifts register allocation across the function — remove one at a time and re-measure.**

Same for `MILO_LOG`→`TheDebug << MakeString`, `MILO_WARN`→`TheDebug.Notify(MakeString)`. ## Linking Sweep (workflow)

A "linking sweep" promotes 100%-matched TUs to `Matching` in `config/SZBE69_B8/objects.json`, making dtk link the source-built `.o` instead of the binary blob — the only way to validate `.o`-level correctness (BSS layout, relocations, section padding), and concrete native-port progress. Independent of byte-level match%. Default `ninja` skips linking; it runs only via `ninja build/SZBE69_B8/main.dol`.

- **Find candidates:** units where `matched_code == matched_data == matched_functions == 100.0`, intersected with non-`Matching` `objects.json` entries. (2026-05: 129 of 1876 TUs were 100% but unflagged → linked count 556→623.)
- **Promote in safe order:** `NonMatching → Matching` first (stale flags), then `Equivalent`, then `LinkIssues` last. Test: `configure.py --map && ninja build/SZBE69_B8/main.dol`. Refresh the linked count: `rm build/SZBE69_B8/report.cache && ninja .../progress.json` (status changes don't invalidate the cache). Revert breakage to `LinkIssues` *with a comment*, not `NonMatching`.
- **Equivalent-promotion is the high-volume tier** (lifted linked 699→748 in one pass). `matched_code_percent` counts only byte-EXACT functions; a unit can show 10% code yet have every function at fuzzy 99–100% (all cosmetic). **Sweep by per-function `fuzzy_match_percent`, not unit `matched_code_percent`.** Candidate = non-linked unit where every unmatched fn is fuzzy ≥99%; ~88% of those are cosmetic (100% normalized, AtLimit register swaps, OFFSET_SWAP, COMMUTATIVE_OP_ORDER, ADDRESS_RELOCATION_NOISE, scheduling reorders). Reject REAL diffs (different instruction count, different non-reloc constants, `cmpw`↔`cmplw`, `beq`↔`bne`, call to a different function). `Matching` = 100% byte-identical; `Equivalent` = functionally-same-but-byte-different (also links from source).
- **Link-only failure classes objdiff cannot catch:** (1) **Multiply-defined globals** — file-local sentinel declared non-static (e.g. `MicClientID sNullMicClientID(-1,-1);` copy-pasted non-static in ~13 TUs; add `static`, no codegen change) or a genuine cross-TU global defined twice (`bool gHostCached` in both System.cpp and DirLoader.cpp; delete the non-owning def). (2) **Redundant virtual declaration in a derived class** — header declares `virtual void Foo(Arg);` as an override with no body, but the original inherited the base's impl → MWCC emits a vtable slot expecting an undefined `Derived::Foo`. Verify via the target's vtable (`bin/analyze-function __vt__<Class>`); if slot N shows `Base::Foo`, delete the redundant decl. Removing it from a *parent* can unblock multiple derived TUs at once.
