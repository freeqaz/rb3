## TL;DR

The fail-red baseline (the `saddleshoe_skin.2` guard-DROP) **reproduces**, but the PLAN's stated
PART-1 root-cause mechanism — *"late lower-body bones lack a clip-free seed → mid-clip first-resolve
rejected `clipPlaying` → V24 guard drop"* — is **REFUTED on the current build, and by the W2.2
baseline's own raw log**. There are **zero `clipPlaying` rejections** anywhere; the load-time clip-free
seed already covers these bones; and the shoe mesh **does complete its rebind** (`mNativeBonesRebound`
→ 1). The residual DROP is a rare **2-5 frame count-in transient** (~2-3% of the mesh's draws) that
the V24 guard already hides — not a persistent missing-seed drop a bind-side fix can durably close.
The only bind-side lever left for the transient frames is `own==bound` rebake (`RB3_BOUND_REBAKE`),
which is the **proven 200-460u rotation-basis failure = the STOP-TRIPWIRE**. Therefore **S2/S3 are
no-ops; W2.6 lands PART 2 (S4 flag-registry cleanup) + this memo only. No PART-1 behavior change.**

## Mechanism — the PLAN's `clipPlaying` hypothesis is refuted

The PLAN (PLAN.md §"Why the shoe drops") predicted the shoe drops because its bones **first-resolve
mid-clip** and are rejected with `missWhy="clipPlaying"` (BandCharacter.cpp:1396) for lack of a
clip-free seed. **Measured, on HEAD *and* on the W2.2 baseline:**

- **`[HEAD_REBIND_PENDING] why=` breakdown is identical across all runs and contains NO `clipPlaying`:**
  - HEAD rep3 (drop run): **91 `unresolvable` + 24 `boundRebakeOff` + 0 `clipPlaying`**.
  - W2.2 baseline `raw-default.log`: **91 `unresolvable` + 24 `boundRebakeOff` + 0 `clipPlaying`**.
- **The load-time clip-free seed already covers the bones.** `[REST_SEED] poll=0` seeds **105–109
  bones per member** into `mNativeRestPose` at the deterministic gender-bind deform pose, before any
  clip. Later mid-song seed attempts are `SKIPPED (clip playing)` but every one is `added=0` — nothing
  was left to seed. So `rp != end` for these bones: there is **no missing clip-free seed**.
- **`saddleshoe_skin.2` is not in the pending log at all.** It resolves distinct **clip-free** (the
  count-in beat clock is frozen — `mDriver->FirstPlaying()` is false on the resolving Poll), takes the
  normal clip-free `else` capture path (:1399), and rebinds. The 2 DROP frames are the inherent
  1-Poll latency between the LOD mesh streaming in during count-in and the next `RebindHeadHandsAtRest`
  Poll completing it — **not** a seed gap.
- The one lower-body mesh that *does* go pending, `tightdistressedpants_resource.1`, is
  `why=unresolvable` (a genuinely missing bone `bone_legs-ring1.mesh`), which a rest-seed cannot fix.

**Conclusion:** the plan's PART-1 premise (a clip-free-seed coverage gap for late lower-body bones)
does not exist on this build. It was inferred from the in-file comment at BandCharacter.cpp:1367, but
that comment's `clipPlaying` framing is not borne out by the very W2.2 log it cites.

## Why S2 (lower-body rest-capture coverage) would be a no-op

1. **The pre-seed S2 would add is already effectively present.** `NativeCaptureRestPoseAfterDeform`
   already seeds every collected mesh's bones clip-free at load (`added=105+`), and the shoe bones
   resolve clip-free anyway — so seeding them "by name earlier" changes nothing about when the mesh is
   *processed* (which is gated on the mesh being in the collected target set, i.e. after it streams in).
2. **The S2 completion branch is unreachable.** It mirrors `RB3_HANDS_BIND_FIX`, which is gated on
   `mDriver->FirstPlaying()` (clipPlaying). That predicate **never fires** for the shoe bones, so the
   branch is dead code for this residual.
3. **The only lever for the 2-5 transient frames is `own==bound` rebake** (`RB3_BOUND_REBAKE`), which
   the code (:1231-1242) and the C8 deep-dive already proved reintroduces the **200-460u R·sin(θ)
   smear** — exactly the STOP-TRIPWIRE this item is forbidden to trip. PART-1 is engine READ-ONLY, so
   the alternative (defer drawing the mesh until rebind completes, or make the guard lineup-aware) is
   out of scope.

## Branch decision

**STOP / diagnosis-only.** This matches PLAN.md §Subtasks W2.6.S1 branch #2 ("a rotation-basis
failure the bind side cannot fix"), refined by evidence: the shoe bones *do* have a clip-free seed and
*do* rebind, and the residual is a benign guard-hidden count-in transient — there is no missing-seed
gap for a bind-side fix to close, and the only remaining bind-side lever is the proven tripwire.

**Consequence:** W2.6 lands **PART 2 (S4 flag-registry cleanup) + this memo only**. There is **no
PART-1 behavior change**, so exit criteria 1 (flag-OFF byte-identical) and 5 (`HandsBindOracle` green)
hold trivially — no new flag, no new code path. `RB3_FOOT_REST_CAPTURE` is **not introduced**; S4
should therefore drop it from the classification set (or mark it `not-implemented`), registering only
`RB3_HANDS_BIND_FIX` and `RB3_SKEL_REBIND_FULL` per PLAN.md §W2.6.S4.
